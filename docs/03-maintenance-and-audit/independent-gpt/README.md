## Repository-specific doctrine

Preserve these boundaries:


Unknown provider/model/version/source/review state remains unknown. Missing evidence remains missing. Conflict remains visible unless a real adjudication layer exists.

## Execution-evidence discipline

Keep these separate:

```text
checker/scanner source present != executed
executed != passed
passed != scientific validity
historical pass != current pass
structured state != scientific verdict
```

Unrun checks are `NOT_EXECUTED`. Unobserved scheduler/workflow execution is `EXECUTION_NOT_OBSERVED` when material. Contract/source inspection is not execution evidence.

Do not fabricate scanner runs, research-workflow runs, provider calls, model identities, test results, citation checks, evidence-sufficiency judgments, or independent reproduction.

## Repair boundary

When drift is confirmed:

1. identify the owning implementation/configuration/document;
2. identify every machine rule, router, operator guide, or current explanation that must stay synchronized;
3. make the smallest semantically complete repair;
4. preserve dated/historical bodies unless correcting their own point-in-time fact;
5. verify the aggregate branch diff against the exact base;
6. refresh current-main and live-overlap state before delivery.

A correction changes current interpretation forward. It does not pretend later knowledge existed during an earlier execution.

## Delivery contract

For an actual repair:

- use one bounded maintenance branch per repository/owning task when practical;
- coalesce Daily/Weekly labels when they own the same real correction;
- record checks run and checks not run;
- create one **Draft PR** against current `main` after aggregate-diff verification;
- stop for maintainer review;
- do not auto-merge, force-push, or write maintenance repairs directly to `main`.

A Draft PR is a review boundary, not proof of runtime, test, scientific, or merge success. Final doctrine and merge authority remains with the maintainer.

## Public boundary

This kernel does not publish or reconstruct private Jules prompts, repository memory, hidden reasoning, credentials, or unrelated operator context. Repository-visible governance may preserve the effect of a rule without copying private control text.
