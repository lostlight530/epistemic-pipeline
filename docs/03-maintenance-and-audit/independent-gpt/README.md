## Repository-specific doctrine

Preserve these boundaries:

```text
claim indexed != claim true

heuristic score != probability
```

Unknown provider/model/version/source/review state remains unknown. Missing evidence remains missing. Conflict remains visible unless a real adjudication layer exists.

## Execution-evidence discipline

Keep these separate:

```text
checker/scanner source present != executed
executed != passed
passed != scientific validity
historical pass != current pass
structured state != scientific verdict
```

Unrun checks are `NOT_EXECUTED`. Unobserved scheduler/workflow execution is `EXECUTION_NOT_OBSERVED` when material. Contract/source inspection is not execution evidence.

Do not fabricate scanner runs, research-workflow runs, provider calls, model identities, test results, citation checks, evidence-sufficiency judgments, or independent reproduction.

## Repair boundary

When drift is confirmed:

1. identify the owning implementation/configuration/document;
2. identify every machine rule, router, operator guide, or current explanation that must stay synchronized;
3. make the smallest semantically complete repair;
4. preserve dated/historical bodies unless correcting their own point-in-time fact;
5. verify the aggregate branch diff against the exact base;
6. refresh current-main and live-overlap state before delivery.

A correction changes current interpretation forward. It does not pretend later knowledge existed during an earlier execution.

## Delivery contract

For an actual repair:

- use one bounded maintenance branch per repository/owning task when practical;
- coalesce Daily/Weekly labels when they own the same real correction;
- record checks run and checks not run;
- create one **Draft PR** against current `main` after aggregate-diff verification;
- stop for maintainer review;
- do not auto-merge, force-push, or write maintenance repairs directly to `main`.

A Draft PR is a review boundary, not proof of runtime, test, scientific, or merge success. Final doctrine and merge authority remains with the maintainer.

## Public boundary

This kernel does not publish or reconstruct private Jules prompts, repository memory, hidden reasoning, credentials, or unrelated operator context. Repository-visible governance may preserve the effect of a rule without copying private control text.

1. Establish `repository / role / canonical task ID / logical period / timezone / cutoff / producer / run ID`. Distinguish Native, independent A1, independent A2, D7/D10/D14/D30, Governance, Correction, and Reconciliation.
2. Read exact latest `main`, owning contracts, canonical paths/blob SHAs, relevant open/Draft PRs and active overlaps, recent merged changes, dependencies, and revision-matched runner/Actions results. Historical summaries are dated evidence, not live state.
3. Determine Native Daily/Weekly/Monthly/Special/Stage eligibility under each repository's actual contract. Exclude not-yet-due periods from the missing-input denominator; keep `NOT_DUE`, `BLOCKED`, `UNKNOWN`, `NOT_EXECUTED`, `NOT_COMPUTED`, and legitimate negative results visible.
4. Do not equate a file, external source, PR merge, configured workflow, passing test, independent AI review, and human approval. Each is a separate evidence claim with its own version, producer, run and time boundary.

### Native → Independent A1 → Independent A2

5. Native output follows repository-owned IDs, dependencies and actual execution evidence. A governance note never substitutes for producer research, formal scanner, runtime, effect receipt, or source verification.
6. **Independent A1 = MonthStart → N−1**, not yesterday alone. Enumerate all applicable month-to-date Daily, Weekly, Monthly, Special and Stage inputs. 7. Prior A1 source reviews may be inherited only when exact path/blob SHA and governing contract still match. Mark inherited and newly inspected coverage; correct only real defects and leave valid sources unchanged.
8. Each legitimate A1 run uses its own original PR. **A2 starts only after that original A1 PR is merged and reread from a fresh `main`**; pending Drafts, future successors and cleanup do not satisfy this dependency.
9. **Independent A2 = MonthStart → N**. Maintain the full month's unified source/evidence/relationship state, not only Day N. Identify supported `STRENGTHENED`, `WEAKENED`, `CHANGED`, `CONFLICT`, `INVALIDATED`, `INHERITED`, `UNKNOWN` transitions and their provenance/counterevidence.
