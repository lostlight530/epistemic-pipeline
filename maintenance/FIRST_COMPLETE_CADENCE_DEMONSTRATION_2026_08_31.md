## 1. Daily demonstration

Command

```bash
python core/maintenance_cadence.py daily --as-of 2026-08-31
```

Daily asks whether demonstrated local evidence-stack drift has appeared

```text
Are canonical evidence and documentation paths present
Did a decorative project profile version reappear
Did forbidden GitHub-governance architecture appear
Is Manifest calibration stale for the daily horizon
Did provider/model/version handling start guessing unknown values
Did score wording drift toward probability
Did conflict visibility or claim-transfer constraints drift
```

Daily does not request canonical hashes or historical inventory

Expected structural shape

```text
cadence: daily
period_status.calendar_month: calendar-month-close
period_status.stage: closed
baseline_sha256: {}
history_snapshots: []
```

Do not infer

```text
no finding -> claim truth
runtime structure aligned -> evidence sufficiency
provider metadata present -> output validity
```

## 2. Weekly demonstration

Command

```bash
python core/maintenance_cadence.py weekly --as-of 2026-08-31
```

Weekly reconciles the evidence stack as a system

```text
runtime implementation
↔ Manifest
↔ Research Contract
↔ Claim Audit Contract
↔ Claim Transfer Contract
↔ assertion-basis / coverage contract
↔ README / Architecture
↔ Agent / Contributor / Customization guidance
↔ Frontier Alignment
↔ cross-repository profile names
```

Special weekly questions

```text
Did trace/checkpoint/provenance/claim audit/claim transfer/envelope collapse into one object
Did a conflict disappear during handoff
Did a heuristic score become described as probability
Did provider identity become inferred rather than reported
Did audit coverage become provenance soundness or quality
Did a historical phase note become a current scientific verdict
```

Weekly requests

```text
canonical SHA-256 baseline
historical snapshot inventory
```

When all canonical paths exist, up to **20 canonical hashes** are generated by the scanner
The hashes must be generated at execution time and are not fabricated in this demonstration

Historical inventory uses the configured `*_DAY_CONSOLIDATION.md` and `STAGE_*.md` patterns

Interpretation

```text
hash != semantic equivalence
coverage inventory != provenance soundness
weekly consistency != evidence sufficiency
```
